Geokode

A self-hosted geocoding service written in Rust. Forward and reverse geocoding, autocomplete and batch lookups over addresses and places.

Rust Self-Hosted FST + R-tree REST API Docker Ready AGPL-3.0-or-later

Features

Forward Geocoding

Text query to coordinates through an FST prefix index. Main Street and Main St match the same records. Each result says whether the query was a whole indexed key (exact), the start of one (prefix) or a typo fallback (fuzzy).

Places

OSM place=* nodes and administrative boundaries are indexed as settlements. jasper finds the town before Jasper Avenue, and Jasper, Alberta still finds a town tagged without its province, at confidence 0.6 or lower.

Reverse Geocoding

Coordinates to the nearest addresses through an R-tree. Confidence drops with distance. A point outside the data coverage returns nothing, and places are never returned.

Autocomplete

Prefix search for search boxes. An optional lon/lat bias reranks only the first limit * 8 matches by distance.

Batch

Forward geocode a list of queries in one request. They run one after another with no cap on request size, so keep batches small.

Address Parsing

Splits on commas by part count into street, city and state, plus house number, postal code and country when there are enough parts. Directionals and unit numbers are dropped for matching.

Data Sources

OpenAddresses CSV, GeoJSON and OpenStreetMap PBF. The index is built in memory at startup and geokode calls no external APIs.

Docker

Tagged releases publish ghcr.io/geolang/geokode. The compose file adds Prometheus on port 9090. Put your own data at ./data/addresses.csv first, no sample data ships.

Optional JWT Auth

Set GEOKODE_JWT_SECRET and the geocoding endpoints require an HS256 bearer JWT with sub, exp and role claims. Leave it unset and every request is allowed. Health, readiness and metrics stay public. The compose file sets the secret to change-me-in-production.

Fuzzy Fallback

A query with no index hit is compared against every indexed key by edit distance, up to 2 edits, returning at most 5 results.

GeoLang

ViewTopia's fly-to search box and the GeoLang agent's geocode_place tool call /forward. Both fall back to public Nominatim on their side.

API Endpoints

GET /forward?q=123,+Main+St
Forward geocode, text to coordinates
GET /reverse?lon=-89.65&lat=39.78&limit=5
Reverse geocode, coordinates to the nearest addresses
GET /autocomplete?q=main&limit=10&lon=-89.65&lat=39.78
Prefix search, lon and lat optional
POST /batch
Forward geocode each string in {"queries": [...]}
GET /health
Service status and record count
GET /healthz
Liveness probe, 200 while the process runs
GET /readyz
Readiness probe, 503 until the index holds records
GET /metrics
Prometheus request counters

Quick Start

# Docker: the container exits without /data/addresses.csv
mkdir -p data
cp /path/to/addresses.csv data/
docker run -p 3000:3000 -v "$PWD/data:/data:ro" ghcr.io/geolang/geokode:latest

# From source, the file extension picks the parser (.csv, .geojson, .pbf)
cargo install --path crates/geokode-cli
geokode serve -d region.osm.pbf --bind 0.0.0.0:3000

curl "http://localhost:3000/forward?q=123+Main+St,+Springfield,+IL"
curl "http://localhost:3000/reverse?lon=-89.65&lat=39.78"
